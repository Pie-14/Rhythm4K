---

> 这个项目的核心不是「能玩 osu!mania 谱面」——那是现成的。
> 核心是**谱面生成**：给一段音频，估出 BPM、对齐节拍、按难度把音符铺在真实鼓点上。
> 下面「[自动生成谱面](#自动生成谱面)」一节解释了具体怎么做，以及现在能到什么水平。

## 三分钟试一下

1. 解压 → 双击 **`启动游戏.bat`**
2. 点「**从音乐自动生成谱面**」→ 选一个 mp3
3. 选难度 → 开始

几秒钟后你就有谱面了。**不需要找谱、不需要转换格式、不需要联网。**

另外两条路也能玩：拖入 `.osz` / `.osu` 打现成谱面，或者点「内置示例曲」看效果。

## 生成质量

用 64 首有人排谱面作为基准对比（同一首曲子的「人写的」和「机器写的」）：

| 指标 | 人排 | 生成 | 说明 |
| --- | --- | --- | --- |
| 音符与鼓点的时间偏差 | — | **3.8 ms**（中位） | 落点吸附到真实起音，不是硬套网格 |
| 同列连打率（0.5 拍内） | 4.3% | **0%** | 键型模式库 + 两道兜底 |
| 长条比例 | ~10% | **10%** | 长度 0.5~1.5 拍随机 |
| 每小节密度（普通） | 6.8 | 6.8 | |
| 相邻小节自相关 | 0.65 | 0.66 | 人排是「一段一段」的，不是逐小节随机 |
| BPM 精度（判对的那部分） | — | **0.000%** | 吸附到整数，3 分钟漂移 < 0.05 秒 |

**不吹的部分**：BPM 检测准确率 63%（±3% 内），完全估错的还有 34%——所以设置里留了手动填 BPM 的输入框。
多 BPM 的歌（中途变速）目前只按单一 BPM 处理，后段会逐渐错位。

## 特性

**谱面生成**
- 一首 mp3/ogg/wav → 三档难度，几秒出谱
- 密度按**每秒音符数**定，不随 BPM 漂移（简单 3.0 / 普通 5.0 / 困难 8.5 音/秒）
- 落点吸附到真实起音，切分音、三连音、演奏的微时序都能跟上
- 键型用交错式排键（1234 / 4321 / 1243 / 1423 / 3241…），不会一直敲同一列
- 长条按「同列后方有没有音」决定长度，不会和后面的音符打架
- 相邻乐句能量相似时沿用前一句的键型（50% 概率左右镜像）

**游戏**
- **直接吃 osu!mania 谱面**：拖入 `.osz` / `.osu` / 整个曲目文件夹即可
- **普通音符 + 长条**，任意键数（4K 默认键位，5/6/7K 自动切换）
- **背景图 + 背景视频**：读 `.osz` 里 `[Events]` 指定的素材；`.flv` 也能放（自己解容器 + WebCodecs）
- **仿 osu!lazer 的版式**：逐列色相、圆角音符、音符形状的判定靶区、右侧 hit error 条
- **音频时钟驱动**：以 WebAudio 的 `currentTime` 为准，带输出延迟补偿和判定偏移校准
- 满分 1,000,000，判定 `PERFECT / GREAT / GOOD / BAD / MISS`
- 完全离线，`file://` 双击就能跑

## 自动生成谱面

### 怎么做的

1. **分析**：降采样到 22 kHz，分低/中/高三个频段算包络 → 上升沿 → 自适应阈值挑打击点

2. **估 BPM**：谱流自相关出候选 → 用「分段对齐稳定性」选出候选 → **在候选附近细搜周期和相位，
   再吸附到整数 / 半整数**。人写谱的 BPM 几乎都是整数值，这一步把 120.18 收成 120.00，
   否则 3 分钟会累积漂移掉整整一拍。
   候选里刻意**不含三连音比例**（2/3、3/2、3/4…）——它们能对上切分节奏，是估错的主因。

3. **定密度**：先算这一档难度「每秒几个音」，再换算成「每拍几个音」——**可以是小数**（比如 1.5），
   用累积器实现。不要按「八分 / 十六分」定层级：同样是八分，120 BPM 是 4 音/秒、200 BPM 是 6.7 音/秒。

4. **铺格**：每拍的能量决定这一拍的细分层级（1 / 2 / 4 个音），并限制「相邻拍最多升一级」，
   避免高潮段突然暴增。安静段落降级但至少保留一个音，保证四分音符填充率。

5. **落点吸附到真实起音**：网格只决定「这一拍出几个音」，具体落在哪由音频决定——
   取该拍时间窗内最强的几个真实起音。同一时刻的多个音会先合并（保证和弦严格同时），
   最后再吸附到 **1/12 拍**细网格（三连音的最小单位）。

6. **分列**：沿音符序列跑一个 GRU（看前 8 个音的列和间隔），输出每个音符落在四列的概率；
   和弦预算按 8 拍窗口分配，避免开头抢光名额。

7. **键型**：连续单音段按人排的模式库重排，再加两道兜底——同列 0.5 拍内不重复、相邻音不同列。

8. **乐句重复**：相邻 8 拍的乐句如果能量曲线相似，沿用前一句的列序（50% 概率左右镜像）。

9. **长条**：约 10% 的音符，长度 0.5~1.5 拍；同列后方有音就不重叠，两条之间至少隔 0.9 拍。

10. **收尾**：每小节密度上限（目标的 1.35 倍），防止局部暴增。

### 模型是怎么来的

权重是离线训练的，推理全在浏览器里（一首 3 分钟的歌约 100 ms）：

| 模型 | 做什么 | 结构 | 产物 |
| --- | --- | --- | --- |
| 阶段 B | 音符落在哪一列 | GRU（历史 8 个音） | `www/js/stage2.js` |
| BPM 选择器 | 从候选里挑对的那个 | 逻辑回归 + 11 个特征 | 内嵌在 `autochart.js` |

训练数据是 254 张有音频的 osu!mania 4K 谱面（从 osu! 抓的 940 张里筛出能解出音频的）。
训练脚本和评估口径都在 `tools/training/` 和 `tools/bench/` 里，可以复现。

### 还可以怎么改

- **手动指定 BPM**：准备页有输入框，检测错了直接填真值，重新生成立刻对齐
- **换难度**：就地重新生成，不用重新选文件

## 导入谱面

三种方式，随便挑：

1. 把 **`.osz`** 拖进窗口（自动解包，谱面和音频一起读出来）
2. 把 **`.osu` + 音频文件**一起拖进来，或拖整个歌曲文件夹
3. 点「选择 .osz / .osu」或「选择文件夹」

要求：

- 必须是 **osu!mania**（`Mode: 3`），`CircleSize` 决定轨数
- 音频文件名和谱面里 `AudioFilename` 一致（放同一个文件夹就行）
- 只支持普通音符和长条；`Slider` / `Spinner` 会被忽略
- 变速 / SV 特效谱面不支持（音符到达时间仍然准确，只是下落速度不做变化）

## 判定与计分

| 判定 | 时间窗 | 权重 |
| --- | --- | --- |
| PERFECT | ±25ms | 300 |
| GREAT | ±45ms | 200 |
| GOOD | ±80ms | 100 |
| BAD | ±110ms | 50 |
| MISS | 超过 ±150ms | 0 |

- **满分 1,000,000**：每个音符等分 `1e6 / 音符总数`，按判定权重计入，
  所以全 PERFECT 正好 1,000,000，分数 ≈ 准确率 × 1e6。连击不加分，只计数。
- 长条在**头部**判定；按住到尾巴（容差 110ms）算完成，提前松手算断连；头部没接住则整条变暗
- 判定总是偏一侧时，看右侧的 hit error 条就知道该把「判定偏移」调正还是调负
- 设置里有**延迟校准**：播一串节拍，你在高音时敲键，它算出平均偏差。
  注意偏移**只影响判定时机，不挪动音符位置**

## 背景图与视频

读 `.osz` 里 `[Events]` 段：

```
[Events]
0,0,"BG.jpg",0,0          ← 背景图
Video,-45,"optc.flv"      ← 视频（自动识别起始偏移）
```

| 容器 | 处理方式 |
| --- | --- |
| `.mp4` `.webm` `.mkv` `.mov` `.avi` | 交给 `<video>` 原生播放，编码不支持就退回背景图 |
| **`.flv`** | **自己解容器 + WebCodecs 解码** |

`.flv` 这一路值得说明：浏览器内核没有 FLV 解复用器（Flash 时代的格式），但 osu 老谱面里大量是这种。
好在里面的编码通常是 H.264，Chromium 能解。所以 `www/js/flv.js` 自己解析 FLV tag、
取出 AVCC 码流和 `AVCDecoderConfigurationRecord`，喂给 WebCodecs 的 `VideoDecoder`，
解出来的画面画进离屏 canvas，再当背景图用。

注意 B 帧：FLV 存的是**解码顺序**，PTS 是乱序的，必须按 DTS 喂，否则会 `EncodingError`。
放不了一律退回 `BG.jpg`，不会黑屏。

## 开发

纯静态，没有构建步骤：改完 `www/` 里的文件，刷新页面就是最新的。

```
www/                 游戏本体（纯静态）
  index.html
  css/style.css
  js/core.js         .osu 解析 + 判定引擎（纯逻辑，无 DOM，可在 Node 里测）
  js/audio.js        WebAudio 主时钟（延迟补偿、暂停恢复）
  js/flv.js          FLV 解复用 + WebCodecs 解码
  js/render.js       Canvas2D 绘制
  js/demo.js         内置示例曲（程序合成音频 + 谱面）
  js/autochart.js    音频 → 谱面（分析 / BPM / 节拍 / 铺格 / 分列）
  js/seqmodel.js     列模型宿主（阶段 B 的推理入口，约 1.3 MB）
  js/stage2.js       阶段 B 权重：音符分列
  js/app.js          界面流程 / 输入 / 主循环
tests/               三层测试 + DOM/音频桩
tools/bench/         生成质量与 BPM 准确率的评估脚本
tools/training/      训练管线（可选，需要 PyTorch + 数据集）
launcher/            启动器源码（C#）与图标
启动游戏.bat          可移植启动入口
重建启动方式.ps1      生成桌面快捷方式
build.ps1            重新编译启动器 exe
package.ps1          打包成可分发 zip
```

## 已知限制

- 自动生成的谱面是**机器谱**：节奏和键型对齐了鼓点，但没有人工编排（段落叙事、刻意的难点、和旋律的呼应）
- 生成的 BPM 有 34% 概率完全估错（多数是倍速关系），需要手动填
- 多 BPM 的歌（中途变速）不支持
- 变速 / SV 谱面不支持
- 不支持自定义皮肤贴图（配色和形状是内置的）
- `.flv` 只支持 H.264；VP6 / Sorenson H.263 的老 FLV、DivX 的 AVI 放不了
- 没有成绩保存、排行榜、谱面编辑器
- 需要 Chromium 内核（Firefox 的 WebCodecs 支持不全，视频背景可能失效）
