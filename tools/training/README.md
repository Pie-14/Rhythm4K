# 训练管线（可选）

游戏本体**不需要**这些脚本——`www/js/seqmodel.js` 和 `www/js/stage2.js` 里的权重已经是训练好的成品。
这里放的是**怎么重新训练它们**，给想复现或改进模型的人参考。

## 需要什么

| 依赖 | 说明 |
|---|---|
| Python 3.10+ | 我用的是 3.12 |
| PyTorch（CPU 版就够） | 训练在 CPU 上跑，单轮几分钟 |
| numpy | 特征与打包 |
| 谱面数据集 | 见下 |

## 数据从哪来

- 谱面：osu!mania 4K 谱（`.osu`），当年我是从 osu! 官网/镜像批量下载的
- 筛选条件：`Mode: 3`（mania）且 `CircleSize: 4`（4K）
- 音频：从对应的 `.osz` 里解出来的 mp3/ogg

脚本里默认路径是 `D:\AI4K\...`（`cache/` 放梅尔特征、`pcm4/` 放 22050Hz 单声道 f32），
换机器时要改脚本顶部的 `WORK` 常量。

## 三个模型

### 1. `train_seq.py` + `export_seq_js.py` → `www/js/seqmodel.js`

舞台 A：在梅尔频谱 + 节拍特征上，用**膨胀卷积**预测「每个 16 分格放不放音符」。
感受野约 ±4 秒，输出每格一个概率。

- 输入：33 维/格（24 梅尔 + 4 拍内位置 + 4 小节位置 + 1 能量）
- 结构：6 层膨胀 1D 卷积（dilations 1,2,4,8,16,1，64 通道）
- 产物：`seqmodel.js`（base64 float32 权重）

### 2. `train_stage2.py` + `export_stage2.py` → `www/js/stage2.js`

舞台 B：沿音符序列做 **GRU**，决定每个音符放哪一列。
输入 = 梅尔帧(24) + 前 8 个音符的列 one-hot + 前 8 个间隔。

> 这一层是为了解决「全挤在一列」——逐格独立判断无法建模按键历史。

### 3. `train_beat.py` + `export_beat.py` →（已不再使用）

按「拍」生成：先判断这一拍有没有音，再选细分掩码。
**0.4.0 起生成器改成了「按每秒音符数铺格 + 落点吸附到真实起音」，这个模型不再参与生成**，
脚本保留是因为它验证过「拍覆盖率」这个指标很有用。

## 评估

- `audit.py`：对比人排谱与自动谱的统计（密度、间隔、和弦、长条率）
- `bpm_features.js` / `train_bpm_sel.py`：BPM 候选选择器的特征与训练
- `build_bpm_gt.py`：从 `.osu` 的 `TimingPoints` 抽真值 BPM，建 64 首的回归集

我用的验收口径（都在项目根的 `.verify/tools/` 里）：

| 指标 | 脚本 | 目标 |
|---|---|---|
| 每小节密度 / 相邻小节自相关 | `bardiff.js` | 自相关 0.65 左右（人排实测） |
| 同列连打（0.5 拍内） | `bardiff.js` | < 5% |
| 落点与起音偏差 | `select.js` | 中位 < 5ms |
| BPM 精度 | `bpmbench.js` | 中位误差 0.000% |

## 注意

- 权重是 **float32 base64** 直接内嵌进 js 的，所以 `seqmodel.js` 有 1.3 MB
- 推理全在浏览器里跑，3 分钟的歌约 100 ms（只用舞台 B）
- 训练数据只有 254 张有音频的谱面，泛化能力有限——想明显提升得先扩数据
